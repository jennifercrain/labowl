Rubber Duck Debugging & Pseudocode Reframing

Help students explain their code and compare it with the logic they intended.

Rubber Duck Debugging

Rubber duck debugging is a well-known technique in programming. When programmers explain their code out loud, they often discover the issue themselves. In a Programming Lab session, the Peer Navigator acts as the “rubber duck” and invites the student to walk through their code step by step and explain what each part is supposed to do.

You Might Say

  • “Walk me through what this section of your code is supposed to do.”
  • “Explain what should happen when the program reaches this line.”

As the student talks through the logic, they often notice gaps in their thinking or places where the code does not match their intention.

This strategy works especially well during Locate the Block and Analyze What’s Happening.

Pseudocode Reframing

Sometimes students struggle because their code does not match the logic they intended. Pseudocode reframing asks the student to describe the logic in plain language before looking at the code.

You Might Ask

  • “If you were explaining this to a friend, what steps should the program follow?”
  • “What should happen first?”
  • “What happens after that?”

Once the student describes the steps, they can compare them to their code and see where the logic diverges. This strategy works well during Locate the Block and Analyze What’s Happening.

Practice Both Strategies

Choose a strategy and respond as the Peer Navigator. Each scenario has three opportunities to practice.
